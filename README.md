# 知识产权护照

周报生成 Skill 的一次上架审核。Markdown 转换器使用 MIT 许可，十二套报告模板使用独立的演示商业许可。移除模板并附完整 MIT 声明可以发布基础版；专业版还需要匹配项目、买方和模板版本的授权凭证。

## 在线体验

[打开审核工作台](https://zhongbanhuan.github.io/ip-passport-monad-blitz/)。选择“载入已购买的示例项目”后检查上架条件，即可复核一笔已确认的 0.1 测试 MON 授权。该演示调用 Monad 测试网合约，审核记录保存在当前浏览器。平台对接使用下述 Next.js 服务端 API，可持久保存审核记录。

示例项目为 `weekly-report-pro`，购买交易位于区块 `81474180`，使用 `149418` gas。签发方在这笔购买中收到 `100000000000000000` wei。[测试网交易](https://testnet.monadscan.com/tx/0x9923fedcd83bbee4168beced31d558ddab9345e8f50eee91099761bd44283ed6)

演示合约的发行地址是一次性测试账户，已登记报价可继续购买、已有凭证可独立复验。团队要持续签发新报价或登记私有版本时，须用自己保管的测试钱包按下文部署。示例素材为 AI 辅助生成的演示材料，其来源记载在固定仓库版本中。

## 本地演示

需要 Node.js 22 和 npm。在项目目录运行：

```sh
npm ci
npm run compile
npm test
npm run build
npm run demo:local
```

打开 http://127.0.0.1:3000 。启动脚本在回环地址运行一次性 Ganache EVM，部署同一份合约、创建两个临时账户、发布报价并真实执行一笔本地转账。终端输出凭证 ID，公开交易数据保存在 `.data/local-receipt.json`。重新启动会得到全新的本地链。合约演示的本地币仅供这一进程使用。

**三分钟演示**　先用默认设置检查，展开每个组件的理由。移除模板、附 MIT 声明后再次检查，下载基础版 ZIP。载入已购买的示例项目，检查并导出专业版审核记录与 ZIP。在“凭证复验”导入这两份文件，先用原项目复验，再改一个项目标识观察拒绝理由。

**创作版本**　在“作者登记”选择本地文件、生成随机盐与版本承诺，下载证据包。再次选择原件与证据包可以在浏览器本地核对。登记交易只发送承诺与父版本等字段；遗失备份会妨碍重算。链上时间表示承诺被登记的时间。

## Monad 测试网部署

操作方先核对演示素材、权利声明和签发地址，使用有测试 MON 的专用钱包。部署工具仅接受 Monad 测试网或本地开发链。通过进程环境提供 `PASSPORT_DEPLOYER_KEY`。运行 `npm run deploy -- --write-env` 将部署合约、登记版本与 0.1 MON 报价，并在新建的 `.env.local` 写入公开部署参数；随后运行 `npm run dev`。请将运行时需要的公开参数同步到正式托管环境，签名密钥仅用于本次部署。RPC URL 会提供给浏览器，应使用公开端点。

买方在测试网连接自己的钱包，阅读条款并签名。合约在同一笔交易内写入凭证、向收款方支付约定金额；服务端依据已配置的合约和签发方重新读取合约状态、最终确认区块、事件和交易回执。测试网资金及地址见 [Monad 开发者文档](https://docs.monad.xyz/developer-essentials)。`node scripts/testnet-demo.mjs` 提供临时测试账户的端到端演练，实际部署结果以区块浏览器和脚本回读为准。

## 独立复验和数据

- `GET /api/config` 返回公开网络配置、固定材料、报价状态与可选示例凭证。
- `POST /api/check` 接收 `projectId,buyer,purpose,components,files,grantId?`。固定用途为 `paid-skill-distribution`。客户端可调用 `buildManifest(includeTemplates,includeNotice)` 生成已知示例清单。
- `GET /api/grants/{id}` 从已配置的链读取授权、交易和签发信息。
- 公开核验允许任何人输入地址复查。真实平台应从已认证账户和自己保存的项目记录取买方与项目标识，再调用审核接口。此演示的“发布”操作交付发布包与审核记录。
- `POST /api/package` 对相同输入重新审核，通过才生成实际发布 ZIP。
- `POST /api/inspect` 对平台导出的 ZIP 直接重算文件摘要。返回清单可用于再次调用 check。演示使用未压缩条目，最大包 256 KiB。
- 开源声明与商业条款的完整文本随核验包导出。未知文件、版本变化及 Apache-2.0 等复杂情形进入人工复核。摘要针对有序文件路径与内容指纹组成的清单，同内容 ZIP 可以独立复验。
- 本地审核记录存放在 `.data/audits`。Sites 部署使用 D1 的 `audit_records`。请求中的钱包、项目标识、分发清单与交易凭证属于审核记录；私人原稿与证据包由作者保管。
- 将 `example/source.bundle` 克隆到空目录即可独立查阅固定版本。示例源码与模板仅按各自目录的条款处理，`RIGHTS.md` 说明演示来源与范围。
- 每个发布 ZIP 的根目录都包含本项目编写的 `SKILL.md`。基础版与专业版使用相同入口，只在包内含模板时读取模板。上架审核会单独核对入口文件的内容指纹。上游组件及其许可固定在[示例版本](https://github.com/ZhongBanhuan/ip-passport-monad-blitz/tree/65871101083b67d0209b57dee22ff908818b6905)。
- 此版本支持单个登记的模板版本与条款。升级目录时须保留历史快照和旧核验规则，才能继续自动处理历史材料。

## 发布与赛后试点

标准 Next.js 主机可运行 `npm run build && npm start`，配置持久化的审核目录。Sites 构建在相同 Next 构建后运行 `node scripts/build-host.mjs`，复用相同规则与 API，并应用 `drizzle/0000_audit.sql`。

运行 `node scripts/build-pages.mjs` 可在 `dist/pages` 生成面向 GitHub Pages 的公开演示。该版本将同一套审核逻辑与合约读取代码打包为浏览器应用，通过 IndexedDB 保存本地记录。公开 GitHub 仓库包含完整 Next.js 后端，Sites 项目标识由托管者单独配置。

试点以五位作者、两名审核或采购人员为对象。请作者提供一次真实分发的仓库版本与许可，记录可直接复用和需单独授权的文件。请审核员用相同包完成一次上架，统计人工追问次数、误判收费次数和缺权订单通过购买或移除组件后完成发布的比例。采购测试以审核接口和审计导出为计价对象。
